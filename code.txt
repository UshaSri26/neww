1. Purpose
Webhooks are used to automatically trigger Jenkins builds when code is pushed to GitHub.
They remove the need for polling and enable real-time CI.

2. Requirements
1. GitHub repository
2. Jenkins running on localhost (port 8080)
3. ngrok installed
4. Jenkins GitHub plugin
5. Pipeline job configured with “Pipeline script from SCM”

3. Start ngrok and Expose Jenkins
Run the following command inside the ngrok folder:
ngrok http 8080
ngrok generates a public HTTPS URL, for example:
https://abc12345.ngrok-free.dev -> http://localhost:8080
Copy the HTTPS URL.

4. Set Jenkins URL
Path: Manage Jenkins ? Configure System
Set:
Jenkins URL: https://abc12345.ngrok-free.dev/
Save.

5. Create Pipeline Job (for webhook testing)
1. Jenkins ? New Item ? Pipeline
2. Pipeline ? Definition: “Pipeline script from SCM”
3. SCM: Git
4. Repository URL:
5. https://github.com/<username>/<repo>.git
6. Branch:
7. */main
or
*/master
8. Save.

6. Configure GitHub Webhook
Go to:
GitHub ? Repository ? Settings ? Webhooks ? Add Webhook
Fill:
Payload URL
https://abc12345.ngrok-free.dev/github-webhook/
Content-Type
application/json
Event type
Just the push event
Click “Add Webhook”.
GitHub sends a test request. If successful, it shows:
? 200

7. Test the Webhook
1. Open any file in the GitHub repo
2. Make a change
3. Commit and push
Jenkins should automatically start a build.
In the Jenkins console output, you will see:
Started by GitHub push
This confirms the webhook is working.

8. Troubleshooting
IssueReasonWebhook shows red cross (×)Wrong Payload URL or ngrok stoppedJenkins not triggeredBranch mismatch or wrong SCM config404 Not FoundMissing /github-webhook/ at end of URL403 ForbiddenCSRF protection; GitHub plugin missingngrok URL changedngrok restarted; must update in GitHub and Jenkins
9. Important Notes
1. Webhook URL must always end with:
2. /github-webhook/
3. ngrok must stay running during testing.
4. If ngrok restarts, the URL changes and webhook must be updated.
5. Jenkins must use “Pipeline script from SCM” for webhook-triggered pipelines.

1. Purpose

Jenkins Email Notification is used to automatically send emails when a build succeeds, fails, or becomes unstable.

2. Required Plugin

Email Extension Plugin (email-ext)

This plugin enables “Editable Email Notification” and supports build triggers.

3. Gmail Preparation (Mandatory)

Open: https://myaccount.google.com

Enable 2-Step Verification

Go to: App Passwords

Create App Password

App: Mail

Device: Windows

Copy the 16-digit app password
(Use this in Jenkins SMTP password)

4. Jenkins Global Configuration

Path: Manage Jenkins ? Configure System

A. Email Notification (Basic SMTP)

Used for simple send-mail support.

SMTP Server: smtp.gmail.com

Use SMTP Authentication: Yes

Username: your Gmail

Password: Gmail App Password

Use TLS: Enabled

Use SSL: Disabled

SMTP Port: 587

B. Extended Email Notification (email-ext plugin)

Used for job-based email triggers.

SMTP Server: smtp.gmail.com

Credentials: Gmail + App Password

Use SSL: Enabled

Use TLS: Disabled

SMTP Port: 465

5. Add Email Trigger to a Job

Path: Job ? Configure ? Post-build Actions

Select: Editable Email Notification

Recipient List: your email

Subject: Build Status

Content: $BUILD_STATUS

Triggers to select:

Success

Failure

6. Test Email

At the bottom of Configure System:
“Test configuration by sending test email”

7. Important Ports

587 ? TLS (SSL disabled)

465 ? SSL (TLS disabled)

8. Common Errors and Reasons
Error	Reason
SSLException: unsupported or unrecognized SSL message	Wrong SSL/TLS settings or wrong port
Authentication failed	Wrong password (must use Gmail App Password)
SMTP connection failed	Wrong port configuration
Editable Email Notification missing	Email Extension Plugin not installed
9. Pipeline Script Example (for email-ext)
emailext (
    subject: "Build Status: ${currentBuild.currentResult}",
    body: "The build result is ${currentBuild.currentResult}",
    to: "yourmail@gmail.com",
    attachLog: true
)

tomcat:
pipeline {
    agent any

    environment {
        TOMCAT_HOME = "C:/Program Files/Apache Software Foundation/Tomcat 9.0"
    }

    stages {
        stage('Checkout') {
            steps {
                // Clone your GitHub repo
                git branch: 'master', url: 'https://github.com/suryaakshaya/mavenweb.git'
            }
        }

        stage('Build') {
            steps {
                // Run Maven build
                bat 'mvn clean package'
            }
        }

        stage('Deploy to Tomcat') {
            steps {
                // Copy WAR file to Tomcat webapps folder
                bat "copy target\\mavenweb.war \"${TOMCAT_HOME}\\webapps\\\""
            }
        }

        stage('Start Tomcat') {
            steps {
                // Start Tomcat server
                bat "\"${TOMCAT_HOME}\\bin\\startup.bat\""
            }
        }

        stage('Verify Deployment') {
            steps {
                echo 'Application deployed! Open http://localhost:8080/mavenweb'
            }
        }
    }

    post {
        always {
            echo 'Pipeline finished!'
        }
    }
}
